# ข้อมูลให้ AI — หน้าผู้ดูแลแบบเรียบง่าย

- เมนู `/admin/knowledge` เปลี่ยนชื่อเป็น “ข้อมูลให้ AI” ตาราง 3 คอลัมน์: แนวคำถาม / ข้อมูลคำตอบสำหรับ AI / จัดการ
- ไม่แสดงสถานะ เวอร์ชัน ตัวเลขรอตอบ หรือเหตุผลทางเทคนิคบนหน้าหลัก รายละเอียดเพิ่มเติมพับไว้ในฟอร์ม
- กดบันทึกใน UI แล้วส่ง `status: published` เสมอ AI ค้นได้ทันที ไม่มีปุ่มเผยแพร่แยก
- API บันทึกที่ไม่ระบุ status ใช้ published เป็นค่าเริ่มต้น แต่ explicit draft/disabled ยังรองรับสำหรับความเข้ากันได้ ไม่เปิดใช้งานข้อมูลร่างเดิมอัตโนมัติ
- ข้อมูลส่วนกลางกับสาขายังแยกสิทธิ์เหมือนเดิม can_edit=0 ไม่มีสิทธิ์เพิ่ม/แก้/ลบ
- การลบจาก UI ต้องยืนยัน และตรวจ version/สิทธิ์ก่อนเปลี่ยนเป็น disabled: ไม่ถูกค้นอีกและยังมีประวัติภายใน ถ้า AI ค้นข้อมูลเก่ามาก่อนหน้า Triage จะปฏิเสธ id/version เก่า
- การล้างข้อมูลเก่าบน local เป็นงานแยก: สำรองครบ 4 ตารางก่อนล้างจริง ไม่ใช่พฤติกรรมอัตโนมัติเมื่อ deploy

## แนวคำถามและคำถามคล้ายกัน

หนึ่งแถวเป็นหนึ่งแนวคำถาม มี aliases หลายรูปแบบ และคำตอบชุดเดียว ผู้ดูแลปรับ aliases ได้ใน “คำถามใกล้เคียงในแนวเดียวกัน”
ส่วน “คำถามที่ควรเพิ่มข้อมูล” พับไว้ด้านล่าง ใช้คิว pending เดิม แต่ไม่ให้ผู้ใช้เลือกสถานะเอง
รวมเพื่อแสดงผลเฉพาะข้อความที่เหมือนกันหลังตัดคำสุภาพ/คำขึ้นต้นและคำแทนที่ที่กำหนด โดยต้องมีสาขา ประเภท และบริบทสรุปเดียวกัน ไม่ใช้ AI summary เพียงอย่างเดียว ข้อความต้นฉบับยังเก็บครบ
กรณีที่ข้อความต่างกันมาก ผู้ดูแลเลือกหลายรายการแล้วเพิ่มข้อมูลเป็นแนวเดียวได้ (ครั้งละไม่เกิน 30 รายการในสาขาเดียวกัน) ต้องตรวจว่าไม่ต่างปี วุฒิ หรือเงื่อนไขสำคัญก่อนบันทึก รุ่นนี้ไม่ทำ semantic merge อัตโนมัติ
การบันทึกคำตอบและเชื่อมคำถามต้นทางเป็น transaction เดียว พร้อมตรวจ version และสิทธิ์ ถ้ามีผู้แก้คำถามระหว่างทำงานจะยกเลิกทั้งชุด ไม่สร้างคำตอบค้างครึ่งหนึ่ง
API รับ `sourceQuestions: [{id, version}]` เพิ่มเติมจาก body เดิม; aliases ยังคงเป็นข้อมูลที่ผู้ดูแลทบทวนและส่งเอง ไม่เติมข้อความกำกวมเป็น alias โดยอัตโนมัติ

## Local reset ที่ดำเนินการครั้งนี้

ยืนยัน Docker context desktop-linux ผ่าน local named pipe และ MySQL hostname ก่อนสั่งล้าง
ล้างเฉพาะ knowledge_answers / knowledge_history / knowledge_questions / knowledge_events ใน Docker local หลังสำรองและตรวจ SHA256
ใช้ DELETE ภายใน transaction ไม่ drop ตาราง ไม่ reset auto-increment ไม่ลบ users/news/uploads หรือ volume
สำรองอยู่ใน `backups/knowledge-2026-09-27T11-13-46-104Z.json` ซึ่งถูก gitignore และ dockerignore
สำรองมี schema และแถวเดิมครบ สามารถใช้กู้ข้อมูลโดยผู้ดูแล อย่ารัน restore ทับข้อมูลใหม่โดยไม่ได้ตรวจสอบก่อน
อย่ารัน knowledge-import.js --apply หากต้องการให้คลังเริ่มว่าง เพราะจะนำ 26 ข้อเดิมกลับมา
script `server/knowledge-reset-local.js` ไม่ถูกเรียกใน startup และต้องมี confirmation flag พร้อม hostname ที่ตรวจแล้ว ห้ามนำไปรันบน server จริงโดยอัตโนมัติ
